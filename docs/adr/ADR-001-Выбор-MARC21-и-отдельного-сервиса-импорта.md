# ADR-001: Выбор FHIR R4 через отдельный integration-service для модуля интеграции с лабораториями

## Статус
Принято

## Контекст
АИС «Электронная медицинская карта» интегрируется с внешними лабораторными системами, которые присылают результаты анализов в разных форматах: CSV, XML, HL7 v2. Прямой парсинг каждого формата внутри ядра системы (`EMR.Core`) нарушает принцип единственной ответственности, усложняет поддержку при изменении внешних контрактов и повышает риск утечки персональных данных из-за сложности кода обработки.

## Решение
Выделить отдельный микросервис `lab-integration-service`, который:
1. Принимает данные от лабораторий в любом формате (CSV, XML, HL7 v2).
2. Нормализует их в единый стандарт **FHIR R4 (JSON)**.
3. Передает очищенные данные в основное ядро `emr-api` только через строгий контракт.

Новую лабораторию можно подключить без изменения ядра медицинской карты, добавив лишь адаптер в `lab-integration-service`.

## Отклоненные альтернативы
1. **Прямая интеграция по HL7 v2 внутри emr-api:** Отклонено, так как HL7 v2 — устаревший формат, плохо версионируется, а его парсеры в ядре нарушают принцип единственной ответственности и повышают риск ошибок в критичном модуле медицинских записей.
2. **Монолитный импорт внутри API:** Отклонено из-за риска блокировки основного API во время массового импорта результатов анализов. Импорт должен быть асинхронным фоновым процессом.

## Последствия
- Ядро ЭМК остается чистым и тестируемым.
- Поддержка новых лабораторий изолирована в одном сервисе.
- Требуется дополнительная инфраструктура для `lab-integration-service`.
- Необходимо поддерживать актуальность схемы FHIR R4 и маппингов полей.
