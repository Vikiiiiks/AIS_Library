# ADR-001: Выбор стандарта MARC21 и отдельного сервиса импорта для каталога книг

## Статус
Принято

## Контекст
АИС «Онлайн-библиотека вуза» должна интегрироваться с внешними библиографическими базами (eLibrary, РГБ, WorldCat). Эти системы предоставляют метаданные в разных форматах: MARC21, Dublin Core, JSON-LD. Прямая обработка этих форматов внутри ядра библиотеки (`Library.Core`) нарушает принцип единственной ответственности и усложняет поддержку при изменении внешних контрактов. Также требуется поддержка полнотекстового поиска, который невозможно реализовать на сырых MARC-записях без предварительной индексации.

## Решение
Выделить отдельный микросервис `ImportService`, который:
1. Принимает данные из внешних источников в любом формате.
2. Нормализует их в единый внутренний стандарт **MARC21 XML** (как основной формат хранения библиографических записей).
3. Параллельно создает денормализованные документы для поискового движка (Elasticsearch/OpenSearch).
4. Передает очищенные данные в основное ядро `Library.API` только через строгий контракт (OpenAPI).

Новую внешнюю базу можно подключить без изменения кода ядра библиотеки, добавив лишь адаптер в `ImportService`.

## Отклоненные альтернативы
1. **Прямой парсинг MARC21 в ядре (`Library.Core`):** Отклонено, так как библиотеки парсинга MARC тяжелые, имеют много зависимостей и могут конфликтовать с бизнес-логикой выдачи книг. Ядро должно оставаться легким.
2. **Использование только JSON-LD:** Отклонено, так как большинство российских библиотечных систем (РГБ, eLibrary) исторически используют MARC21. Переход на JSON-LD потребует дорогостоящей конвертации на стороне поставщиков данных.
3. **Монолитный импорт внутри API:** Отклонено из-за риска блокировки основного API во время массового импорта тысяч книг. Импорт должен быть асинхронным фоновым процессом.

## Последствия
- Ядро библиотеки остается чистым и тестируемым.
- Поддержка новых источников данных изолирована в одном сервисе.
- Требуется дополнительная инфраструктура для `ImportService` и очереди сообщений (RabbitMQ/Kafka) для асинхронной обработки.
- Необходимо поддерживать актуальность схемы MARC21 и маппингов полей.
